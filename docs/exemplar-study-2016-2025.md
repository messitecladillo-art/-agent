# 2016—2025 高教社杯公开范文结构研究

> 这是产品设计的证据记录，不是“获奖论文排名”或某个模型的胜率报告。样本来自公开展示页与公开文字镜像，所有结论都区分 `observed`、`inferred`、`hypothesis`。

## 1. 研究边界

- **竞赛**：高教社杯全国大学生数学建模竞赛（CUMCM）。
- **时间**：2016—2025；主要观察本科组 A/B/C 题。
- **样本**：13 条来源记录，包含组委会/中国大学生在线展示页、官方摘要、公开逐页文字镜像和一个公开作者仓库的评语记录。完整台账在 `.collab/evidence/T01/source-ledger.csv`，结构矩阵在 `.collab/evidence/T01/pattern-matrix.yaml`。
- **访问**：2026-08-31；只读公开网页，没有发送题面、个人信息或模型密钥。
- **抽样限制**：官方展示页是筛选后的公开集合，二次镜像也不是随机样本；很多 2016、2024、2025 页面以连续图片发布。`image_only`、`UNAVAILABLE` 和“展示页未列具体奖项”均保留在台账中。

## 2. 可观察结构（observed）

| 编号 | 结构 | 在公开样本中看到的形式 | 对工作台的转译 |
|---|---|---|---|
| P01 | 题面覆盖与小问映射 | 摘要按问题编号分别写方法、结果或决策输出 | 每个 Q 都有原题引用、交付物、约束与 claim 链 |
| P02 | 问题分析独立成章 | 题目重述后先解释数据/机理，再进入公式 | 设置“问题分析”门，不允许从模型名直接跳到结果 |
| P03 | 假设与符号显式化 | 独立列出模型假设、符号、边界/个体差异 | 变量、单位、假设、适用域和禁用条件成为结构化字段 |
| P04 | 多阶段模型链 | 统计/机理 → 优化/分类 → 策略/判定 | 用有向链记录上游输出如何成为下游输入 |
| P05 | 算法与实现可追踪 | 具体算法、流程、编码约束与实现步骤并列 | 记录入口、复杂度、停止条件、容差、失败模式和复现命令 |
| P06 | 验证、基准与敏感性 | 回测、交叉检验、仿真再检验、扰动或基线比较 | 验证族按题型选择，并要求 clean-run 与结果 hash |
| P07 | 图表/流程承载结果 | 官方连续页、流程图、角度/产量表、Pareto/时序图 | 图表绑定 claim、数据范围和生成脚本，而非只上传图片 |
| P08 | 优缺点与推广 | 结尾单列模型评价、局限和推广 | 论文门要求写外部有效性和禁用条件 |
| P09 | 指标量化与决策落地 | 完成率、收益、准确率、R²、三级判定等 | 每个数字绑定单位、分母、范围、基线和不确定性 |
| P10 | 独立复核意识（inferred） | 替代算法、扰动、交叉模型或基准比较反复出现 | 独立 reviewer 与作者上下文隔离；单次最优不能直接放行 |

### 代表性观察

- 2018 B203 的公开摘要同时出现 0-1 规划、双目标、启发式、故障仿真和 12 组检验，说明高质量呈现往往是“问题—算法—检验”的链，而不是只列一个算法名。
- 2020 C109 的公开材料把改进树模型与非线性规划、准确率基准和策略收益放在同一条叙事中，提示指标必须连接到决策目标。
- 2021 B050、2022 C155、2023 C228、2025 C023 的公开文字镜像都能看到不同形式的检验、扰动、交叉验证或误差敏感性；这些是结构观察，不是评分因果证明。
- 2018 A440 的官方展示摘要包含降维、能量守恒、非稳态热传导、边界/初始条件、参数估计、有限差分、辐射扩展和约束优化，说明机制题需要显式的物理结构、数值方法与扩展检验。

## 3. 挑战结论（inferred / hypothesis）

独立数学审查对结构归纳做了反驳，见 `.collab/evidence/T03/challenge.md`：

1. 结构共现不能升级为“有这个章节就得分”；标题只有在原题句、变量/约束和结果证据都能回链时才有用。
2. 模型链不等于接口正确。每一条边必须说明符号、单位、粒度、provenance 和禁用条件；链越长不加分。
3. “至少一种验证”只是存在性条件。预测、优化、仿真/物理、机制/政策题需要不同的互补检查。
4. 指标不能脱离基线、切分、单位、分母和不确定性进入论文；漂亮的 R² 或收益不自动代表决策有效。
5. 共享的数据清洗、验证脚本和发布审计应作为共享节点映射到多个 Q，不能复制节点后虚增完成率。
6. 题面缺件或图片正文未复核时必须 `BLOCKED/UNVERIFIED`，不能用占位变量或猜测引用把链填绿。

以上第 1—4 条是当前硬门设计依据；“能降低漏题率/审查时间”的效果仍是 `hypothesis`，需要用真实或合成赛题回放验证。

## 4. 产品验收映射

| 建模产物 | 必备字段 | 未满足时的状态 |
|---|---|---|
| `problem_contract` | 原题句/页码、题型、交付物、约束、来源状态 | `BLOCKED` 或 `UNVERIFIED` |
| `variable_registry` | 符号、含义、单位/量纲、粒度、来源/推导 | 不能进入路线审批 |
| `assumption_registry` | 类别、适用域、禁用条件、可识别性/敏感性 | 只能 `READY_FOR_REVIEW` |
| `route_spec` | baseline、primary、fallback、目标、约束、接口、复杂度、失败模式 | 不能按模型数量排序 |
| `validation_plan` | 题型匹配的两类互补检查、命令、退出码、结果 hash | 数字保持 `UNVERIFIED` |
| `claim_index` | claim class、指标定义、范围、证据、target revision、限制 | 不能写入论文数值 |
| `release_gate` | P0/P1、clean-run、manifest、Owner approval、奖项来源 | 禁止 `ACCEPTED/RELEASED` |
