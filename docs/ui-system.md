# UI 系统与交互规范

## 1. 视觉方向

关键词：**研究室、证据感、克制的未来感、可读性优先**。

- 基底是暖白/浅灰纸张色，避免传统“科技蓝大屏”或纯黑聊天工具的疲劳感。
- 深海军蓝只用于品牌、Owner 控件和高权重动作；青绿表示通过/在线，琥珀表示等待/审批，珊瑚红表示风险，不用颜色直接宣称“正确”。
- 圆角 9–16px，细边框和轻阴影代替厚重卡片；信息密度高但层级清楚。
- `assets/math-field-bg.png` 只做 5–6% 透明度的氛围层；所有事实仍由结构化 DOM 渲染。
- 正文优先系统无衬线字体，数字/哈希/事件 id 使用等宽字体，便于核对；品牌、首屏标题和短甲骨文标记使用项目内置的“青甲骨刻体 / QingJia Oracle Display”。

## 2. 页面构成

### 顶栏

展示项目名、届次/题号、运行时钟、当前协作档位、演示/实时标志、通知、暂停和 Owner 菜单。顶栏的“SIMULATED 演示”必须在 mock 数据下保持可见。

### 左栏：群成员与频道

- Owner 固定置顶，显示最终权限。
- 频道按竞赛生命周期划分：总控、题面与数据、建模方案、算法与仿真、验证与质疑、论文与答辩。
- Agent 卡显示角色、模型、状态、当前 task 和 lease；点击打开权限/任务/验收说明。
- 外部 Agent 以虚线卡显示；未完成 connector/ACK 前显示 `PENDING`，不可伪装在线。

### 中栏：群聊事件投影与建模首屏

阶段条下固定显示 `题面 → 小问 → 模型 → 验证 → 论文`，并给出当前 Q、阻断、路线接口与验证摘要。Q 卡片显示交付物、覆盖字段、最大风险和责任 Agent；完整模型链节点进入控制面板。每条消息由头像、角色、实际模型、时间、事件类型、正文和可展开的 provenance 详情组成；来源、claim class、task/Q、target revision、状态、证据 chip 和动作仍保留在 DOM 中。推荐事件标签：

`TASK / ACK / PROGRESS / PROPOSAL / QUESTION / EVIDENCE / CRITIQUE / REBUTTAL / DECISION / BLOCKER / APPROVAL / RELEASE`

支持：引用 claim、查看原文映射、打开证据、发起反驳线程、请求重跑、@Agent、切换频道、搜索 task/claim/file。

### 右栏：协作控制面

- 建模控制：当前 Q、路线 A/B 的目标、baseline、量纲/粒度、参数来源、适用/禁用、fallback、验证族，以及红/黄/绿评审门矩阵。
- 运行卡：RUN id、input/worktree/control 三种 revision、完成节点、运行时长、待裁决数。
- DAG 卡：状态、负责人、依赖、进度、风险和下一动作。
- 审批队列：只有 Owner 可批准路线、参数、外部传输、合并和发布。
- 证据账本：文件名、来源、hash、provenance、敏感级别、关联 claim。
- 红色门禁不可由 Agent 自行改绿；前端按钮只是服务端状态机的投影。

## 3. 动画原则

动画要说明“发生了什么”，不能制造喧闹：

- 页面进入：三栏以 40–80ms 错峰淡入并上移 6–8px。
- 新消息：单条从下方 8px 淡入，约 360ms；不使用弹跳或长距离飞入。
- Agent 工作中：只使用小尺寸状态点呼吸；不让整个头像持续抖动。
- 进度条：低对比度 sheen 每 2.8s 一次，用于表示仍在运行；不代表质量提高。
- Toast：从右下 20px 上移，250ms 进入，3.2s 后退出。
- 面板/弹窗：遮罩淡入，卡片缩放从 0.98 到 1；点击背景可关闭只读预览。
- 小青龙身份位：`assets/ip/xiao-qinglong-idle-v3.mp4` 仅用于顶栏 36px 品牌槽，静音内联自动播放一次；加载时使用同源 `xiao-qinglong-idle-v3-poster.png`，结束、自动播放失败、媒体错误或减少动态效果时回退 `xiao-qinglong-face-v3.png`。该素材尚未通过严格无缝循环门，不得扩展为全屏/长期背景动画。
- 所有动画遵循 `prefers-reduced-motion: reduce`，关闭非必要过渡。

## 4. 信息真实性

颜色、头像和排序不代表结论正确。真实状态由：

```text
claim class + evidence refs + target revision + independent review + gate
```

共同决定。Mock 数据必须在顶栏和每个事件/证据元数据中标记 `SIMULATED · fixture`，并使用 `fixture:` 前缀的可读 revision；这类 revision 不是完整性证明。真实接入后显示 `LIVE EVENT`、run id 和服务端 hash。没有 artifact manifest 的条目不得显示 `VERIFIED`。

## 5. 断点策略

- ≥1100px：三栏完整工作台。
- 850–1099px：缩窄侧栏和右栏，保留三栏核心信息。
- <850px：左栏折叠，聊天主区优先，任务/证据右栏下移为可滚动控制面。
- <500px：隐藏低优先级频道操作，保留消息、发送、任务门禁和 Owner 审批。

## 6. v9 甲骨文 · 液态玻璃皮肤

- 视觉 token 采用骨纸、墨绿、青铜、朱砂四层；颜色只作提示，状态必须同时有文字/形状。
- 甲骨文是低对比度识别锚点：只在品牌、频道分区和建模首屏留少量“卜/模/证”刻痕，不替代题面、来源或门禁文字。
- 液态玻璃只用于顶栏和打开的右侧检查抽屉（最多两层），消息气泡、证据行和数据卡保持近不透明纸面；`prefers-reduced-transparency` 时自动回退为实色。
- 首屏采用“一条 Q 主线 + 阶段轨 + 一主动作”：次要 revision、变量和模型链通过控制面板/详情展开，完整 provenance 通过每条消息的原生 `<details>` 一键查看。
- 移动端显式把聊天主区放入可见网格列，右侧控制面板作为固定抽屉；验收要求 390px 以上无横向滚动、抽屉 tab 不溢出。

## 7. v10 青甲骨刻体与参考板式

- 字体文件位于 assets/fonts/qingjia/，通过 @font-face 注册；当前为单一 Regular / 400 字重。
- 展示字体只承担品牌名、建模首屏标题、印记和短标签，不用于长正文、证据表格或小于 16px 的密集信息。
- 字体自带的 U+E000–U+E009 私用区印记用于品牌 seal 和小青龙识别锚点；原有图片头像/动作图标继续作为确定性视觉资产与字体加载失败时的回退。
- 参考板式吸收“玉石印记、圆角工作卡、淡青描边、右侧任务轨”的层级关系；建模信息仍以当前 Q、阶段、阻断、路线、验证和 provenance 为主，不以装饰替代语义。
- 字体许可证、修改声明和可重建源数据记录在 docs/fonts/qingjia/README.md 及其 source/ 子目录。

### v11 QQ/微信式群聊信息流

- 聊天主区按“消息流”而不是“居中报告”排布：消息行占满可用列，Agent 消息从左侧、群主消息从右侧对齐；右侧对齐使用 `row-reverse + flex-start`，避免 CSS 主轴反转后落回左侧。
- 每条消息保留头像、成员名和时间；同一成员在 2 分钟内连续发言时，后续消息加 `is-continuation`，隐藏重复头像/元数据但保留缩进，接近 QQ/微信的气泡分组。
- 系统事件使用居中的低对比度胶囊，日期分隔线居中；引用卡通过 `order: -1` 放在正文之前，附件卡最多渲染 4 个，并且只允许同源 HTTP(S) 地址，未通过安全校验的附件显示为不可点击的 `UNVERIFIED` 卡片。
- 模型/角色细节移入元数据 `title` 与可展开 provenance，正文只保留成员名、时间和内容；消息 kind 仍写入 `data-message-kind` 供检索/测试，不让标签淹没对话。
- 回归视口：1440×900、1024×768、768×1024、390×844、360×800；要求 `document/body.scrollWidth === innerWidth`，群主气泡位于聊天列右侧，系统消息位于聊天列中心。

## 8. v12/v13 浮动纸面壳与青甲骨字体边界

- **浮动纸面壳**：页面外层使用暖白纸面与极浅的甲骨纹理，主工作区像一张悬浮在背景上的薄纸；纸壳只承担页面分层，不承担信息表达。边框使用低对比度青玉线，阴影保持短、软、低扩散，禁止把每个消息和每个字段再包成厚重卡片。
- **玻璃的使用边界**：液态玻璃只用于顶栏、悬浮工具条和打开的任务/证据抽屉。消息正文、公式、数据表、证据引用和状态门必须落在接近不透明的纸面上；这样在透明度变化、屏幕录制和低端设备上仍可读。系统开启 `prefers-reduced-transparency` 时使用实色回退。
- **字体职责**：`QingJiaOracleDisplay` 只用于品牌名、首屏短标题、短印记和 2–8 字的文化标签；正文、题面、长说明、表格、按钮动词和错误信息继续使用清晰的中文无衬线字体；哈希、revision、RUN id 和路径使用等宽字体。甲骨字体不可用于替代语义文本，也不可用于小于 16px 的连续阅读。
- **甲骨文字形**：甲骨字符是识别层而非导航密码。`卜 / 题 / 模 / 算 / 证 / 稿 / 库`可作为频道或模块的辅记，但每个辅记必须同时有现代中文名称；私用区印记只做品牌 seal 或 IP 锚点，不参与状态判断。

## 9. v12/v13 群聊层级与移动抽屉验收

- 群聊首屏按四层组织：① 当前 Q、阶段、阻断、Owner；② 消息成员、时间、正文和事件动作；③ 默认收起的 provenance、来源、claim、revision 与 evidence refs；④ 任务 DAG、模型参数、完整运行记录。前两层支持连续阅读，后三层按需展开。
- 视觉减法不得隐藏 P0/P1 信息：当前题目/小问、交付物、阻断原因、责任人、路线接口、验证摘要和审批动作必须常驻或一键可达；装饰性印记、模型长名和低频审计字段不得抢占消息正文宽度。
- 移动端 <850px 隐藏左栏，聊天区占满唯一网格列；任务、证据和知识库通过固定右侧抽屉打开。抽屉需有清晰关闭动作、遮罩点击关闭和可横向滚动但不溢出的 tab；打开抽屉时聊天内容不被重排到零宽列。
- 浏览器验收至少覆盖 1440×900、1024×768、768×1024、390×844、360×800：`document.body.scrollWidth === innerWidth`；群主消息保持右对齐，Agent 消息保持左对齐，系统事件居中；消息 provenance 默认 `open=false`，展开后完整字段仍存在；抽屉 tab 的 `scrollWidth === clientWidth`。

## 10. v13.2 质感增量验收

- **左侧 IP 锚点**：左栏允许出现低对比度、静态的小青龙水印，作为空间记忆点而不是功能按钮；水印不能覆盖频道文字、成员状态或 hover/focus 区域，失去图片资源时必须优雅回退为空白或普通印记。
- **主视觉可见**：建模首屏的主视觉/小青龙场景保持在第一屏可见，但必须让位于当前 Q、阶段、阻断、路线和验证摘要；主视觉是氛围层，不能承载事实、数值或状态结论。
- **角色色带与状态点**：成员行使用窄色带区分 Owner、Coordinator、Scope、Model、Data、Validator、Critic、Paper 等角色；状态点同时配合文字（在线/工作中/等待/阻断/PENDING），颜色不能独立表达成功或正确。
- **Overview 压缩**：overview 只保留当前 Q rail、阶段轨和路线/验证摘要，模型变量、长 revision、完整运行日志进入右侧控制面或 provenance；压缩后仍须保证 Q 标题、交付物、阻断和 Owner 下一动作一键可达。
- **字体加载**：首屏展示字体使用 `font-display: swap` 或等价回退策略；字体未加载时品牌、短标题和甲骨印记仍保持布局稳定，正文不等待字体。验收需检查网络失败/缓存未命中时无文字溢出、无不可读私用区字符。

## 11. v13.5 触感层级与反馈安全带

- **纸面纹理边界**：`oracle-chat-bg-v1.png` 只在聊天平面的边缘出现，中心阅读区保持低对比度；纹理是纸纤维与空间氛围，不得成为壁纸或压过气泡正文。`prefers-reduced-transparency` 时仍以接近不透明的纸面为主。
- **右栏重量分配**：当前运行卡是唯一持续抬起的控制锚点；普通任务、决策与证据行使用低对比度边框和无常驻阴影，hover/focus 才短暂抬升。这样右栏仍保留扫描效率，但不再形成“卡片套卡片”的纵向堆叠。
- **Toast 安全带**：移动端 Toast 先进入 `prepare` 状态，聊天 feed 预留 56px，并在消息区接近底部时重新对齐；消息淡入完成后再显示提示。提示淡出后撤销留白，避免遮住最后一条气泡、输入区或群聊状态行。
- **触感而非喧闹**：边缘高光、短软阴影、按压下沉和轻微 hover 位移表达可交互性；不使用持续抖动、弹跳或大面积玻璃模糊来制造“高级感”。
- **回归口径**：1440×900、1024×768、768×1024、390×844、360×800 均需满足无横向溢出；Toast 出现和消失时，最后消息与 composer 的矩形不相交，且 QingJia 字体/状态文字仍可读。

### 11.1 移动抽屉的清晰度边界（v13.5.3）

- `#panelBackdrop` 与 `.right-sidebar` 必须位于同一个 shell 堆叠上下文；遮罩低于抽屉，不能覆盖抽屉文字。
- 移动抽屉保留纸面渐变和边缘阴影，但不对自身内容使用 `backdrop-filter`；液态玻璃只作用于其后的聊天空间。
- 打开抽屉后仍应能读清 Q、阻断、证据和审批字段；关闭后聊天区恢复原有层级，且不得产生横向滚动。

## 12. v14 质感原则与真实运行限制

v14 的设计语言以“可进入、可停留、可判断”为准，而不是继续叠加装饰：

- 暖纸面是唯一连续底，液态玻璃只用于顶栏、悬浮工具条和按需控制抽屉；消息、公式、证据和表格保持近不透明，避免透明叠层削弱阅读。
- 当前 Q/当前运行是唯一主浮层；普通任务、决策和证据行使用安静清单样式，仅 hover/focus 短暂抬升。边缘高光、短软阴影、按压下沉足以表达触感，不使用持续抖动或大面积模糊。
- 小青龙、甲骨刻痕和 QingJia 展示体承担品牌记忆，不承担状态语义。状态必须同时显示文字、claim class、evidence refs 和 revision。
- 首屏优先级固定为：当前 Q → 阶段/阻断 → 群聊正文 → provenance → 任务控制；低频字段按需展开，不能让装饰抢占消息宽度。

### 12.1 workspace catalog 的界面边界

仓库资料挂载卡应显示 `workspace manifest`、来源 `repo:<relative-path>` 和
`source_integrity=observed`，并与外部资料的 `kbdoc:` 视觉区分。`repo:` 只表示
候选上下文，不得显示成“已验证资料”或自动填入论文结论；manifest 变化时卡片应
提示 stale 并要求重新检索。右侧资料面板可以给出 counts、匹配片段和路径，但不应
一次展开整库内容。

### 12.2 真实运行标识

当前本地 API 仍是 offline-dev：事件可持久化为单进程 journal，模型 adapter、
OIDC/RBAC、签名 relay、语义索引和生产级沙箱尚未默认启用。界面必须把
`SIMULATED · fixture`、`LIVE EVENT`、`PENDING_RELAY`、`UNVERIFIED` 等状态写出来，
不能用绿色、头像或动画暗示正确性。v14 的“高端”验收只在多视口无溢出、字体回退、
Toast/composer 不相交、reduced-motion 和 source/revision 可追溯均通过后成立。

### 12.3 低高度桌面收束（v14.2.11）

当桌面视口高度不超过 760px 时，首屏不再让 hero 和小问卡片争夺聊天空间：
hero 只保留标题与 Owner 状态，Q 轨收束为单行定位器，资料库/能力装配等低频动作
回到控制面；聊天区目标是保留至少两条完整近期消息。该收束只改变垂直留白和次级
说明，不删除题面、阶段、阻断、责任人与证据入口。
