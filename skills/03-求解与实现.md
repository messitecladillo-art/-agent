# Skill 03 · 求解与实现（阶段 2：求解）

> 目标：把模型变成**可复现、可验证、可写进附录**的代码与数值结果。
> 官方导向（总则 2021/2023）：**鼓励对提交的程序和结果进行验证**——验证不是附加分，是官方明示的得分路径。

## 输入 / 输出

| 输入 | 输出 | 落点 |
|---|---|---|
| 模型决策记录（Skill 02） | 可运行代码 + 数值结果表 | 代码 → `models/`，结果 → `experiments/` |
| 赛题附件数据 | 预处理后的干净数据 | `data/processed/`（大文件不进仓库） |

## 1. 实现规范（复现性第一）

1. **固定随机种子**，写入配置；蒙特卡洛报告样本量与置信区间
2. **参数集中管理**（配置字典/文件），正文与附录引用同一套数值
3. **目录约定**：每个子问题一个入口脚本 `models/q<n>_<名称>.py`，数据路径相对仓库根
4. **环境记录**：依赖与版本写进 `models/requirements.txt`；MATLAB 代码注明版本
5. 代码进附录前必须**清空运行环境重跑一遍**验证可运行（提交前清单硬性项）

## 2. 数值结果的生产标准（A/B 题生死线）

1. **结果能对表**：A 题评阅要点常附参考数值（2023 A：第 1 问给出年平均光学效率 0.45、输出热功率 27.57 MW 等一整表参考值；2021 A：基准接收率约 5.6%）。每出一个关键数值，先自查量级
2. **交叉验证要设计**：2023 A 官方给了现成验法——"DNI × 光学效率 ≈ 单位面积年输出热功率"，可用来核验自洽性。主动找这类守恒/自洽关系
3. **约束逐条验证**：列"约束—验证方式—是否满足"表，附验证代码（2021 FAST 题官方逐条列出绳索长度、主索变化 ≤0.07%、促动器行程 ≤0.6m 三类约束要求核验）
4. **决策题给数值判据**：期望成本/利润的具体数值 + 决策变量的具体取值（2024 B 要点）；优化题报告与最优解的接近程度（2024 C：未用最优算法时按"距离"判质）

## 3. 实验记录规范（experiments/log.md 只追加）

每次运行一条记录，格式：

```markdown
## <日期时间> 实验 <编号>：子问题 <n> - <简述>
- 配置：脚本 / 参数 / 种子 / 数据版本
- 结果：关键数值表
- 对表：与参考值/上一轮的偏差
- 结论：一句话（采纳/放弃/待调）
```

没有记录的数值结果 = 不存在（守则红线"落盘才算数"）。

## 4. 分工与节奏

- **Codex** 主责实现（分支 `task/<ID>-<desc>`），每个脚本附最小自测
- 超时预案：单算法跑超 30 分钟无收敛迹象 → 记录并换备选模型（Skill 02 的备选就是为此准备的），不要静默空转（守则 §6）
- 计算量工程意识：先分析极值/最不利位置再动手算（2024 A 评阅要点原文精神），避免无谓全空间搜索

## 5. 常见错误
1. **只交数字不交过程**：光有结果表没有推导与验证——"纯数值计算不构成好论文"（2021 D）
2. **附录代码跑不通**：路径写死、依赖缺失，评审抽查直接露馅
3. **随机结果不固定种子**：评审复现不了，可信度归零
4. **结果与约束不自洽**：方案数字好看但违反题面约束（如年利润与总利润矛盾、种植面积超限——2024 C 明确按此判卷）
