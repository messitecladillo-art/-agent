# 数学建模·数学表达与排版

这个 Skill 处理的是“把模型讲明白并让别人能复核”，不是替用户凭空选择模型、
替代求解器，也不是把某一篇获奖论文套成固定模板。它吸收了一篇用户提供的高分
论文中可观察的共性：小问与模型一一对应、符号和单位先定义、公式由定义推到
离散/算法、判据与结果回链、图表和代码可定位。字体、章节名、页数、编号策略和
配色都必须由本届官方格式与用户选择决定。

## 何时使用

在下列任务中调用本 Skill：

- 起草、重写或压缩中文数学建模竞赛论文，尤其是模型建立、推导、结果解释和结论；
- 将已有 LaTeX、Word 或结构化模型记录整理成可审计的正文与附录；
- 审查公式编号、符号定义、量纲、边界/初值、图表交叉引用、数字一致性和复现链；
- 从一篇优秀论文提炼可迁移的写作/排版模式，或制作团队写作模板。

如果请求只是解一道题、调试一个数值程序或制作装饰性海报，分别交给建模、求解、
验证或视觉 Skill；本 Skill 只在需要论文表达或数学证据链时介入。

## 先决条件与证据口径

在动笔前读取与任务相关的 `problem_contract`、官方格式来源、模型/数据版本和已有
验证记录。缺少其中任何一项时，保留 `BLOCKED` 或 `UNVERIFIED`，不要用范文补空。

所有结论标注来源类别：

- `OBSERVED`：题面、数据、运行日志或渲染页中直接可定位的事实；
- `INFERRED`：由事实抽象出的写作建议，必须说明推理边界；
- `HYPOTHESIS`：尚未验证的路线或效果预期；
- `OFFICIAL_PENDING`：等待本届竞赛官方规则确认的格式要求。

参考论文只保留“页码/版式模式/可迁移规则/不适用边界”四元记录。禁止把论文的
具体地理、参数、临界值、方程组、图、代码、长段落或结论写入新论文或 Skill；
不要将“看起来像获奖论文”描述成获奖保证。详见
[`references/reference-paper-pattern-card.md`](references/reference-paper-pattern-card.md)。

## 输入与输出契约

输入应绑定同一个 `input_revision`（Git commit 或文件清单 SHA-256）：

1. `problem_contract`：竞赛/届次/组别/题号、题面句子、子问题、交付物、约束与页码来源；
2. `variable_registry`：符号、含义、类型（输入/状态/参数/决策/输出）、单位、粒度、来源；
3. `assumption_registry`：假设、理由、适用域、可检验方式、禁用条件和放松方案；
4. `route_spec`：透明基线、主路线、备用路线、接口、复杂度和模型选择理由；
5. `validation_results`：检查类型、范围、阈值、命令、退出码、结果哈希和限制；
6. `claim_index`：正文主张、数值/范围、题目小问、证据、状态和适用边界；
7. `artifact_manifest`：数据、代码、图表、论文源文件及依赖版本的哈希。

最低输出（可由 LaTeX、Word 或其他生成器实现）：

- 论文源文件和可渲染产物；
- `equation_registry`：公式语义 ID、显示标签、输入/输出、单位、前置假设、验证检查；
- `crossref_manifest`：图/表/公式/算法/附录的 label、caption、引用位置、生成文件；
- `claim_matrix`：每个重要数字到结果文件、命令、哈希、验证和限制的回链；
- `render_qa_report`：引擎/字体、页数、缺字、溢出、断页、引用和图表可读性结果；
- `release_checklist`：题面覆盖、数学、复现、版权、匿名和格式门的状态。

结构化字段的最小 schema 和状态机见
[`references/registries-and-evidence.md`](references/registries-and-evidence.md)。

## 标准工作流（可拆装，不可跳过关键门）

### L0 · 锁定范围

锁定竞赛版本、组别、题目、阶段、官方模板、匿名要求和 `paper_style`。把官方硬规
范与范文观察分开；官方来源未确认就写 `OFFICIAL_PENDING`。为每个子问题登记“题面
原句 → 要回答的量/决策 → 交付格式”，避免写成与题面无关的漂亮长文。

### L1 · 建立数学叙事骨架

每个子问题单独形成一条可追踪链：

```text
题面目标 → 观测量/决策变量 → 假设与理由 → 定义/方程/目标
→ 中间推导与边界条件 → 算法/求解器 → 结果与单位
→ 题目语义解释 → 验证/敏感性 → 适用域与限制
```

段落中的“因此、可得、说明、从而”必须能回到上一条公式、数据或验证记录。
不允许从一个模型名直接跳到数字结论；关键跳步要写中间量、尺度或判别条件。

### L2 · 变量、假设与公式门

- 新符号首次出现时同时给出语义、正负/方向约定、单位和粒度，并登记到符号表；
  同一符号全文不得改义。无量纲量明确写“无量纲”或使用统一单位字段。
- 每个方程记录输入、输出、定义域、初值/边界、适用假设和验证方式。加法项、目标
  函数和约束逐项做量纲检查；秒/小时、米/公里、样本级/总体级不得暗中混用。
- 说明线性化、近似、截断、正则化、缺失值处理、边界简化和稳定化的理由；给出误差、
  敏感性或禁用条件。必要时同时保留基线模型，说明复杂路线带来的增量。
- 核心公式使用语义化唯一 ID（如 `eq:q2-mass-balance`），渲染编号交给引擎；正文
  使用 `\eqref`/交叉引用，不手写易漂移的“公式(7)”。

### L3 · 选择证据链模式

不要强行给所有题套同一种“证明”结构，按题型选择模式：

| 模式 | 必写链 | 最低验证 |
|---|---|---|
| 证明/解析 | 定义 → 引理/命题（若需要）→ 条件 → 推导 → 结论 | 边界情形、反例或独立推导 |
| 优化/决策 | 决策变量 → 目标 → 约束 → 求解 → 可行解/权衡 | 可行性、最优性 gap 或基线对比、敏感性 |
| 预测/统计 | 数据定义 → 估计量/模型 → 训练策略 → 预测 | 隔离回测或交叉验证、残差/校准、不确定性 |
| 机制/仿真 | 守恒/状态方程 → 参数与条件 → 离散 → 输出 | 守恒/边界、网格或步长收敛、情景扰动 |
| 混合 | 标明每一段属于哪种模式及接口 | 各模式门分别通过，接口量纲一致 |

验证图表不能装饰性出现：每张图/表都要回答一个已登记的主张，并注明范围、分母、
样本数、不确定性和不能推出的结论。相关不等于因果；相关性题不得写成“导致”而无
识别假设或干预证据。

### L4 · 从连续模型到可复现求解

在正文按“控制关系/目标 → 参数化 → 初值与边界/约束 → 离散或算法 → 稳定/停止条件
→ 输出提取”展开。长公式用对齐环境分行，保留能核对尺度和中间代数的最小步；离散
式说明索引、时间层、边界更新和误差来源。正文给算法接口，附录给可运行代码，不用
代码截图替代推导。

每个结果绑定数据/代码入口、随机种子（若有）、环境版本、命令、退出码和哈希。改变
网格、步长、随机种子或关键参数后，若结果超出预设容差，状态回退为 `UNVERIFIED`。

### L5 · 组织论文与版式

内容顺序优先于视觉模仿。常用拓扑是“摘要/关键词 → 问题重述与分析 → 假设 → 符号 →
逐问模型与求解 → 验证/敏感性 → 评价与推广 → 参考文献 → 可复现附录”，但可按题面和
官方模板调整。每一节开头先说本题为什么需要这一步，结尾回答它对下一步的接口。

`paper_style` 至少声明：页面/边距（以官方为准）、中文/数学/代码字体、标题层级、
公式编号策略（全局或分节）、图表浮动策略、单位格式、代码样式、灰度可读性和输出引擎。
不要把参考论文的 A4、字号、41 页或特定字体当成硬规则。

LaTeX 首选；Word 必须使用可编辑公式和可更新交叉引用。两者共享同一结构化数据层，
不要在两个版本中手改数字、caption 或编号。细节模板见
[`references/derivation-and-layout-guide.md`](references/derivation-and-layout-guide.md)。

### L6 · 独立审查与发布

Writer 不独自批准自己的数学结论。至少安排一名 Critic/Challenger 逐项检查：题面覆盖、
符号冲突、量纲、假设边界、公式/图表/算法引用、数字一致性、验证互补性、代码复现和
版权原创性；再由 Auditor 在干净快照渲染。P0/P1、未验证数字、断链引用、缺失单位、
版权不明或明显溢出时禁止 `RELEASED`。

草稿阶段可以先看警告，不阻断编辑；发布前使用完整 release 门：

```powershell
# draft（允许 HYPOTHESIS/UNVERIFIED，仍记录问题）
python skills/math-modeling-mathematical-writing/scripts/audit_latex_math.py paper --json
python skills/math-modeling-mathematical-writing/scripts/audit_paper_contract.py contract.json --json
# release（锁定官方格式后才运行）
python skills/math-modeling-mathematical-writing/scripts/audit_latex_math.py paper --release --json
python skills/math-modeling-mathematical-writing/scripts/audit_paper_contract.py contract.json --strict --json
```

只有第二条 `audit_paper_contract.py` 命令支持重复的 `--registry <path>` 参数；LaTeX
检查器不读取注册表文件。拆分契约注册表时，把 `--registry <path>` 逐个追加到第二条
命令，严格模式会检查它们的 `input_revision` 是否与根契约一致。注册表合并在根契约
中的最小示例见
[`references/registries-and-evidence.md`](references/registries-and-evidence.md)。

Skill 自检可使用 skill-creator 的验证器。Windows PowerShell 请显式开启 UTF-8 模式，
避免系统代码页误读中文 `SKILL.md`：

```powershell
python -X utf8 "$env:USERPROFILE\.codex\skills\.system\skill-creator\scripts\quick_validate.py" skills/math-modeling-mathematical-writing
```

检查器只能证明结构性条件，不能证明公式数学正确、模型适合题目或结果真实；这些仍需
独立推导、数据审计和人工/代理复核。

## 写作与排版决策清单

提交前至少回答以下问题，并把答案落到 manifest 或报告，而非只在聊天里口头确认：

1. 每个小问是否都有一个明确的输出量/决策和对应正文段落？
2. 每个符号是否先定义再使用，单位、方向、粒度和来源是否一致？
3. 每条关键公式是否有语义 label、前置假设、输入输出和验证记录？
4. 从方程到算法是否保留了必要的中间步骤、边界/初值、停止/稳定条件？
5. 每个数字是否能沿 `claim → result artifact → command → hash → validation` 回放？
6. 图题/表题位置、单位、图例、样本数、来源和正文引用是否完整且互相一致？
7. 摘要和结论是否把数学结果翻译成题目要求的现实语义，而非只报模型名？
8. 结果是否报告范围、不确定性、敏感性和失效边界，避免过度外推？
9. LaTeX/Word 是否在干净环境编译，且无 undefined reference、缺字、溢出、裁切或编号漂移？
10. 是否明确哪些内容来自范文观察、哪些是当前题目证据、哪些仍待 Owner 批准？

## 与本仓库其他 Skill 的衔接

- 用 `01-审题破题.md` 产生 `problem_contract`，用 `02-模型选型与建模.md` 产生路线和假设；
- 用 `03-求解与实现.md`、`04-验证与灵敏度分析.md` 产生算法、结果和验证 manifest；
- `05-论文写作.md` 是正文主笔与章节生产层；本 Skill 在其前后负责数学叙事、公式/图表/代码
  排版与证据回链，完成后交 `06-论文评审与终检.md`；它不是 `05` 的替代品；
- `08-美赛专项.md` 负责英文正文、Summary Sheet 和美赛官方格式；本 Skill 复用同一
  `equation/claim/crossref` 接口，但不覆盖 `08` 的页数、匿名和提交规则；
- `07-范文精析.md` 只提供结构观察卡；本 Skill 的参考论文卡不替代官方规则，也不升级题面事实。

### 交付状态

仅当所有阻塞门通过才标记 `READY_FOR_REVIEW`；通过独立评审、干净渲染、版权/匿名/官方
格式检查后才标记 `RELEASED`。任何“看起来更像范文”的评价都不能替代这些状态。
