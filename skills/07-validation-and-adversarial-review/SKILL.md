# 验证、红队质疑与独立复算

验证不是最后补一张图，而是判断结果能否被相信、在哪些条件下失效。作者不能只用自己
设计的指标自证；单 Agent 也必须模拟独立角色并留下分离记录。

## 输入与输出

输入：model-contract、run-manifest、结果 artifact、假设/参数台账、题型 review signals。

输出：

- validation-report/v2；
- baseline 对比、约束逐条核验、误差/区间、敏感性、反例和独立复算记录；
- open findings（P0/P1/P2）及修复状态；
- claim 可升级/不可升级清单；
- 给 writing/release 的状态和限制。

## 验证层次

至少选择两种性质不同的证据，并说明为何互补：

1. 透明 baseline 或精确小规模对照；
2. 题面参考值、真实观测或外部数据对比；
3. 特例、极限、守恒、单位和边界检查；
4. 隔离 holdout/CV/滚动回测、残差和校准；
5. 参数/输入/网格/时间步/随机种子敏感性；
6. 反例、失效情景、消融或独立重实现。

“测试通过”必须绑定范围、阈值、命令、退出码和 hash。

## 按题型执行

### 预测/统计

按时间、主体或组隔离评估；训练折内拟合预处理；报告 MAE/RMSE/R² 等合适指标、残差、
区间/校准和分层结果。R² 不是因果或泛化证明。

### 优化/决策

逐条列约束、余量、违反率和整数性；给 baseline、gap/局部性、权重或 Pareto 情景；
比较前先确认所有方案可行。启发式报告多实例/多种子。

### 机理/仿真

检查量纲、初边界、守恒/平衡残差、网格/步长收敛、暖机、重复和置信区间；情景变化
要注明只改变了哪些参数。

### 在线/政策

按信息集回放，查未来信息泄漏；写识别假设、反事实范围、利益冲突和不可推广边界。

## 红队问题

独立审查者至少提出：

- 哪条假设最可能失效，能否构造最小反例？
- 哪个参数不可识别或由单一来源决定？
- 结论是否被一个异常值、一个随机种子或一个权重翻转？
- 是否把相关性/拟合/候选资料写成因果/官方规则？
- 方案是否在每条硬约束下可执行？
- 论文数字能否由命令和 artifact 重放？

每个质疑必须有 check 或 evidence；不能用“看起来合理”关闭。

## 灵敏度报告

预先登记关键参数、扰动范围、联合扰动、观察量和翻转阈值。结果不稳时诚实报告边界，
不要挑选有利区间。权重类、预测类、成本类和物理参数分别说明扰动意义。

## 状态门

- 发现硬约束违反、泄漏、量纲错误、结果不可复现：BLOCKED；
- 仅有单一证据或未做关键敏感性：UNVERIFIED；
- 所有关键 finding 关闭、两类互补检查通过：READY_FOR_REVIEW；
- 独立复算和渲染/版权门也通过后才能交 release。
