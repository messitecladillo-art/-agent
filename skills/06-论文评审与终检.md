# Skill 06 · 论文评审与终检（阶段 5：提交前评审）

> 目标：以**评委视角**对成稿做独立评审，把问题消灭在提交前。
> 执行分离红线：评审者不改稿，只出问题清单；修改由写作负责人执行后再复审。
> 工具：`scripts/agents/review.py`（Claude API 独立评审）+ 本 rubric。

## 1. 五条官方金律（评审第一遍：逐条过）

依据官方评阅总则与 2021–2024 评阅要点提炼（breakdown §4.3）：

1. **结果可对表**：评阅要点常带参考数值 → 关键结果量级是否与之吻合？（2023 A 有整表参考值）
2. **定义即得分点**：题目未定义的量（覆盖率、相似度、风险指标）是否先定义、再论证、再使用？
3. **模型 > 算法 > 数值**：完整建模过程是骨架？还是只有算法名字和数字？（纯数值计算不构成好论文，2021 D；2016 A 原文"评阅应该以模型为主，数值结果为辅"）
4. **约束逐条验证**：是否有"约束—验证方式—是否满足"表 + 验证代码？
5. **拒绝模板腔**：每一节是否都在回答本题特有的问题？套话段落按总则压低

### 附：2005–2018 跨年八大共性信号（按出现频次排序，金律的历史证据）

1. **模型合理性是首要标准，数值不是唯一标准**：2008A"模型合理性与优越性是主要评阅标准"；2015A/2017B"主要关注模型是否合理、正确"；2017D 不以人数最少为唯一判据
2. **模型检验/验证是硬性得分点**：2008A"模型检验常被低估"；2017A 问 4 **自行构造数据做模型检验→给予较好评价**；2018A 加随机误差测稳定性；2018B 用 3 组数据检验实用性；2013B **程序运行结果须与论文结果一致**
3. **模型必须针对具体问题，禁止通用套路**：2014A 不接受照搬文献两/三段式；2016B 未考虑本题特殊影响因素的模型"对本问题的价值不大"；2017A 仅用通用模型 + 所有参数一起优化"一般不可能精准标定"；2017D 要针对问题结构设计；2018B **通用启发式/仿真方法不可接受**；2019C/2020C 简单主观套用综合评价"不是好的做法"
4. **定义/指标可多样但须明确、合理**：2009B 指标定义可不同、合理性看语境；2008B 须多角度、至少两个方面
5. **数据缺失/异常必须说明处理**：2012A 明示；2013A 视频数据提取与纠错；2007A 抽样数据是相对的
6. **敏感性/误差分析被明确鼓励**：2005B、2014A 问 3 专门一问、2017A 问 4 噪声影响、2018A
7. **鼓励创造性与自主提问**：2005B 问 4 自己提出问题并解决"是重要组成部分"；2013B 扩展"可考虑适当加分"
8. **自 2004 年起官方不再提供参考解答，只给评阅要点**："要点仅给一种可行方法，各种数值/工程/近似方法按实际评判"——方法可不同，评的是合理性与完整性

### 附：命题人点评的论文五大通病（2010A/2011B 命题人评述，评审时逐条排查）

① 理论与实际脱节（模型精度高却忽略测量噪声/标定漂移）② 误用判别准则 ③ 参数估计不做校准 ④ 缺可靠性分析 ⑤ 缺不确定性量化与敏感性分析。另 2011B 命题人点名：只按最短时间指派不顾工作量均衡、平台选址无论证、符号不规范、"循环模型"（自我重复无推进）。

## 2. 分维度评分（评审第二遍：国赛四维度 + 美赛取向）

**国赛**：① 模型假设的合理性 ② 建模的创造性与实用性（权重最高）③ 求解的正确性 ④ 表达的清晰性
**美赛**：清晰度 / 有效性 / 可行性 / 假设合理性 / 灵敏度与稳健性；Summary Sheet 单独审

每维度给：评级（优/良/中/差）+ 证据（引用论文原文位置）+ 改进建议

## 3. 分题型专项检查（评审第三遍）

| 题型 | 专项检查点 |
|---|---|
| A | 参考数值对表；约束逐条核验；"用数值论证而非仅仅算出"；仿真设计与有效性说明 |
| B | 关键概念定义与论证；未默认正态性（2024 B）；理论/仿真均有具体过程与明确结果；决策有判据与数值 |
| C | 不是纯数据分析（有模型、有不确定性分析）；异常值处理交代；时间效应考虑；结果按实际意义校验 |
| D/E | 置信区间；算法全局最优性讨论；在线优化未用未来信息；期望损失与统计显著性 |

## 4. 三类反面教材自查（评审第四遍：逐条打勾）

1. **摘要堆空话**：术语流水账、无核心成果、缺数值结论
2. **图表潦草**：默认配色、模糊截图、无标题无单位、坐标轴不标注
3. **格式混乱**：公式样式不一、编号跳号、符号不统一、引用格式混搭

## 5. 提交前检查清单（终审逐项执行）

- [ ] 摘要含问题-方法-结果三要素与关键数值
- [ ] 每个子问题都有明确数值答案
- [ ] 灵敏度分析至少覆盖 2 个关键参数
- [ ] 图表全部有标题、单位、图例
- [ ] 符号全文统一、公式编号连续
- [ ] 附录代码可运行（清空环境重跑过）
- [ ] 无错别字、页数合规
- [ ] 关键结果与官方评阅要点参考数值量级吻合
- [ ] 题目未定义的量均已先定义、再论证、再使用
- [ ] 每条约束都有对应的验证说明（列表 + 验证代码）
- [ ] 无"模板腔"段落：每节都在回答本题特有的问题
- [ ] 结论与建议均出自模型计算结果，而非先入为主（2016 B 问 4 考察点）
- [ ] 模型、算法（程序）、结果三者一致（2020 B 评阅关注点，与 2013 B 互证）

## 6. 评审流程（标准操作）

1. **自动评审**：`python scripts/agents/review.py paper/论文.md`（或 .tex/Word 导出的文本）→ 报告落 `notes/reviews/`
2. **diff 评审**：大改动用 `--diff main...HEAD` 只审增量
3. **人工终审**：Qoder 按本 rubric 四遍过一遍，合并机器报告，输出终审清单
4. **阻塞项归零**：所有"阻塞"级问题修复后复审，才可提交
5. 赛后复盘：官方评阅要点公布后，用同一 rubric 自评，差距写入 `notes/`

## 7. 评审报告格式（review.py 已内置要求）

每个问题必须包含：① 严重程度（阻塞/重要/轻微）② 位置 ③ 问题描述 ④ 修改建议
