# 备赛与演练流程

目标是把资料变成可重复能力，而不是收藏更多文件。每周产出可运行、可审查的 artifact。

## 六个循环

1. 评阅校准：按年份读官方评阅，记录重复信号和反例；
2. 范文模式：按题型/算法选多篇，生成 pattern cards，不复制；
3. 算法实验：每个家族完成最小算例、基线、测试和失败说明；
4. 论文训练：从结构化 registry 生成一页推导、三线表和图表，做渲染 QA；
5. 限时演练：用未精析的真题跑固定或 DIY 流程，记录时间和门失败；
6. 复盘固化：将发现写入 review regression、方法卡和缺口清单。

## 每周验收

- 至少一份新 problem-contract；
- 至少一个方法有适用/禁用/验证卡；
- 至少一次 clean-run 和独立质疑；
- 至少一页论文通过公式/图表/引用结构审计；
- 复盘有具体失败、修复和下一轮测试。

## 4–8 周可执行排程

可按队伍基础压缩或展开，但每一周都要留下可复现产物，而不是只完成阅读：

| 周次 | 主目标 | 必交工件 | 通过条件 |
|---|---|---|---|
| 1 | 题面与评阅校准 | 2 份 problem-contract、评阅信号表 | 原句/单位/约束可回链 |
| 2 | 数据与统计基线 | data-contract、无泄漏切分、1 个 baseline run | raw hash、指标定义和失败说明齐全 |
| 3 | 机理与优化 | 1 个 ODE/PDE 或 LP/MILP 小算例、推导卡 | 量纲/边界/可行性检查通过 |
| 4 | 仿真与不确定性 | 固定种子仿真、重复/区间报告 | 独立重跑误差在预注册容差内 |
| 5 | 范文到论文 | 2 张 pattern card、2 页推导、三线表/图 | 不复制原文，公式/图注结构审计通过 |
| 6 | 限时整题 | 一次 24–72 h 演练 release draft | 每小问有输出，关键 finding 关闭 |
| 7 | 对抗与答辩 | red-team、反例集、答辩矩阵 | 能回答参数、假设、边界和复现问题 |
| 8 | 清洁复现与复盘 | release pack、回归清单、缺口 backlog | 干净环境重跑且 Owner 签字 |

若只有 4 周，将第 1–2 周、第 3–4 周、第 5–6 周、第 7–8 周分别合并；不能删除
数据、验证和复盘工件，只能减少题目数量或方法数量。

## 单次训练记录

每次练习写 `drill_record`：题面/资料 revision、限定时间、选用 preset 或 DIY 图、
每个阶段开始/结束时间、失败门、fallback、最终状态和下一轮修复。训练分数不要只看
最终答案；至少按覆盖、数学链、可复现、验证、论文表达五项分别评分，并保存评分依据。

## 资料使用顺序

国赛：01 评阅/真题 → 05 算法代码 → 06 写作 → 07 工具；
美赛：02 题与论文 → 05 代码 → 06 美赛写作；
基础补课：08 课程 → 09 参考书。其他赛事规则始终单独锁定。

课程和书籍只能补概念或检索词，不能替代当届题面、官方规则、实验数据或独立验证。
